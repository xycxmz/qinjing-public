{{$.T "Statistical methodology"}}

{{$.T "Exact binomial intervals"}}

{{$.T "Every rate carries a 95% Clopper-Pearson exact interval computed from the beta distribution (no normal approximation). Detection rates use a two-sided interval; the false-positive rate uses a one-sided 95% upper bound. A 0-FP run is not a zero-width interval: 0/120 still reads as <= 2.47% at 95% confidence."}}

{{$.T "Independence limitation"}}

{{$.T "These intervals assume independent Bernoulli trials. Corpus cases are correlated (generated variants, single-family benign personas), so the effective sample size is smaller than the case count and repeated runs are not independent. The intervals are therefore optimistic; treat them as bounds on this corpus, not on operational deployment."}}

{{$.T "No total score"}}

{{$.T "Micro (pooled over all class instances) and macro (mean of per-class rates) are side-by-side views with no natural total score. They weight classes differently and must not be collapsed into a single ranking number."}}

{{$.T "Precision versus false-positive rate"}}

{{$.T "Precision = detected attack cases / (detected + FP violations); FPR = FP violations / evaluable benign cases. A high detection rate can coexist with a high FPR, so a precision-FPR scatter reads both axes together rather than ranking on one. The ideal corner is high precision and low FPR (top-left)."}}

{{$.T "Reproducibility and the input triple"}}

{{$.T "Every run links its raw evidence: the markdown report (which carries the corpus-sha256 / exec-log-sha256 / alerts-sha256 triple), the exec log, and the alerts. The triple pins the exact input bytes (docs/03 D9, hash-must-cite): a change to any byte of the corpus, exec log, or alerts is a different input and must not be mixed. Re-running the same triple under a different scorer calibre reproduces the cross-calibre comparison, and the raw report lets a reader verify every number against the same bytes (HF Open LLM Leaderboard per-model detail)."}}

{{$.T "Version governance and archiving"}}

{{$.T "Run history is grouped by benchmark version.
