# Qinjing 秦镜 — an open benchmark suite for host intrusion detection

> **秦镜** (Qín Jìng, "the Mirror of Qin"): the legendary mirror in the palace
> of the First Emperor that revealed what was hidden in a person's heart —
> the origin of the idiom 明镜高悬 ("the bright mirror hangs high"), the emblem
> of impartial judgment in the Chinese courtroom. Its courtroom companion is
> the beast **獬豸** (xièzhì), which butted the guilty on sight. The xièzhì
> detects; the qinjing verifies. This project is the mirror: it shows whether
> a host intrusion detection system actually sees.

## What this is

A self-contained, live-executable evaluation suite for HIDS capability:

- **Corpus** — attack cases mapped to MITRE ATT&CK tactics/techniques, plus
  benign operations that must stay silent. Every case annotates its required
  binaries and its expected outcome class (`detectable` / `gap` / `silent`).
- **Runner** — executes every case on a Linux host under throwaway uids with
  per-case session isolation, probing binary availability first; cases whose
  binary is missing are scored `NOT-RUN`, never as misses.
- **Scorer** — attributes alerts to cases by execution time windows, produces
  the detection matrix (HIT / PARTIAL / MISS / NOT-RUN) and per-tactic
  coverage stats.
- **FP checker** — tight-window (±2.5 s) false-positive audit with
  cross-talk discrimination between adjacent cases.

## Why another benchmark

| existing | does | doesn't |
|---|---|---|
| Atomic Red Team | executes ATT&CK-mapped tests | no scoring/attribution — you eyeball your own alerts |
| ADFA-LD & friends | static system-call datasets | logs, not live runs; dated attack mix |
| MITRE ATT&CK Evaluations | rigorous vendor evaluations | closed, vendor-only, not runnable by you |

Qinjing targets the gap: **runnable, scored, product-agnostic**. Any HIDS
that can export alerts (JSON) can be graded against the same corpus.

## Safety

- Cases only target TEST-NET (`203.0.113.0/24`), loopback, or the link-local
  metadata endpoint (`169.254.169.254` — never routed off-host).
- Every case carries an impact rating (`none` / `temporary` / `destructive`);
  destructive cases need a disposable target VM.
- Attack cases run under per-case throwaway uids; the benign group runs as
  root by design (owner decision, 2026-11-16) so its argv noise exercises
  real system operations — therefore targets must be disposable VMs, and
  side effects stay confined to `/tmp/qinjing-*` paths.
- Cases designed to be safe to execute on an isolated test VM — never on
  production hosts.

## Quickstart

```
# on the target Linux host (bash + setpriv + coreutils, python3 to score)
tools/runner.sh corpus/qinjing.yaml          # execute 1075 cases, isolated uids
# tools/runner.sh corpus/qinjing.yaml --only T02,F01   # explicit subset run
# export YOUR HIDS alerts to canonical JSON (see docs/03 section 4;
# reference implementation: adapters/xiezhi/alerts_to_canonical.py)
python3 tools/scorer.py corpus/qinjing.yaml /tmp/qinjing-exec.log alerts.json
python3 tools/fpcheck_tight.py /tmp/qinjing-exec.log alerts.json
bash tests/selftest.sh                       # toolchain self-check, no Linux needed
```

## Provisioning

`data/provisioning.tsv` is generated by `tools/gen_provisioning.py` from
the corpus bin fields (regenerate after any corpus change; never
hand-edit). Per signal class it lists the cases, the required binaries
(the same `command -v` criterion the runner probes), the provisioning
gap for a CentOS-style target, and whether any case needs a reachable
remote peer or listener. Dual disclosure on the 2026.11 corpus: **52
classes corpus-level, 14 effectively evaluable on the bare reference
bench** (every case's bin present; the rest carry sim-missing-bin cases
that score NOT-RUN, five classes sim-only), and **21 service-dependent
classes** that additionally need a reachable peer - counted separately,
never merged into the bin criterion.

## ATT&CK coverage

The corpus is anchored to MITRE ATT&CK. Measure and show its footprint:

```
python3 tools/attack_coverage.py corpus/qinjing.yaml     --out-md coverage.md --out-layer coverage.json
```

`coverage.md` gives the per-tactic table and per-technique case split;
`coverage.json` is an ATT&CK Navigator layer (score = case count) loadable
at the Navigator web UI. A pre-generated layer for the 2026.11 corpus
ships at `coverage/coverage-2026.11.json`. The vendored matrix snapshot
(`data/attack-enterprise.txt`) is regenerated from the official
ATT&CK STIX bundle (attack-stix-data tag v20.1, MITRE custom license,
see NOTICE) via `tools/gen_attack_matrix.py`; unknown-id and
revocation alarms double as upstream-drift detectors, and
`tools/anchor_lint.py` keeps the vocabulary-technique anchor chain
consistent.

Scoring semantics (HIT / PARTIAL / MISS / NOT-RUN, the two calibres, the
attribution identity gates) are documented in the `tools/scorer.py`
module docstring. The corpus and alert schema and the lint rules are in
the `tools/parse.py` module docstring.

## Dashboard

A self-contained Go server renders the corpus's own coverage as a local
web UI: totals, ATT&CK tactic coverage, technique heatmap, signal-class
distribution, and the reference-bench provisioning disclosure.

```
cd dashboard && go build -o dashboard .
./dashboard --addr 127.0.0.1:8090 --data dashboard_data.json
```

`dashboard_data.json` is regenerated by `python tools/gen_dashboard_data.py`
(schema-gated, byte-identical on rerun). Building the dashboard needs
Go 1.26 or newer; `tools/gate.sh` step 4 (build, vet, test) skips loudly
without a Go toolchain. Every number on the coverage pages is a measured
property of the corpus. The scores page is a "pending real-machine run"
placeholder: `runs[]` ships empty and no number is invented.

## Development split

`tools/family_check.py` checks a public/holdout split with zero family
leakability: cases of one signal family (or benign role sub-family) never
straddle the two sets. The deterministic split walks families in sha256
order inside each pool and takes whole families into holdout until the
pool target is met. On the 2026.11 corpus it lands at public 896 /
holdout 179 cases (16.7%, rebalanced from 23.9% toward the 15% target);
the benign pool runs at its T3 floor (holdout 32 / public 88, both sides
above the 30-case minimum denominator, so FP rates are computable on
each side). It is a development split, not a blind evaluation set: ~74%
of cases are template-generated.



## 中文定位

**秦镜**是给 HIDS（主机入侵检测系统）照的镜子：一套可现场执行、自带判分
口径的开源测评集——攻击用例锚定 MITRE ATT&CK、良性运维用例考察误报，跑

## Status

**Incubating, v0.3 in flight** — 1075-case corpus (120 benign / 955 attack
/ 3 kill-chain buckets / 15 tactics, every case impact-rated and anchored
to a 52-class product-agnostic signal vocabulary, incl. server-profile
techniques from webshell drops and Redis persistence to container escape,
linker hijack, shell-config persistence, indicator removal and K8s pod
exec), runner (uid isolation, session-tree isolation,
optional marker attribution, pre-flight dry-run), dual-calibre scorer,
tight-window FP checker, reference adapter with acceptance layer, and a
197-assertion selftest under a local push gate. Apache-2.0. Derived from
the internal benchmark of the [xiezhi](https://github.com/xycxmz/xiezhi-public)
HIDS project and generalized: ATT&CK-anchored expectations instead of
product-internal rule ids, product-agnostic alert ingestion.
